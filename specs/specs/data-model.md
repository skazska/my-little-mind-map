# Data Model Spec

Spec IDs in this document use the `S-DM-*` prefix. See [glossary](glossary.md) for terminology and the [specs index](../specs.md) for cross-cutting notes.

Satisfies: @E-TEXT (`S-DM-N*`, `S-DM-ND*`), @E-INTERLINK (`S-DM-L*`, `S-DM-V*`, `S-DM-S*`, `S-DM-NR*`), @E-MUTATE (`S-DM-MV*`).

## Labels

### S-DM-L1

Label: single word: alphanumeric + hyphens, lowercase `^[a-z0-9-]+$`. Used for categorization and search.

### S-DM-L2

Label: cross-cutting across spaces and notes.

### S-DM-L3

Label unused: cleared automatically.

### S-DM-L4

Label content: name, statistics.

## Named Note Views

### S-DM-V1

View: named notes view with stored filters.

### S-DM-V2

View id: `view://<name>`.

### S-DM-V3

View content: filters, statistics.

## Spaces

### S-DM-S1

Spaces: containers for notes, hierarchical, independent and manageable.

### S-DM-S2

Space name: alphanumeric + hyphens, lowercase; spaces in display name are replaced with hyphens.

### S-DM-S3

Space id: domain notation, names separated by dots from leaf to root: `this-space.parent...root`. Allows referencing spaces as URI: `space://this-space.parent...root`.

### S-DM-S4

Space content: name, description, labels, statistics.

## Notes

### S-DM-N1

Notes: primary content units, hierarchical: trees.

### S-DM-N2

Note content: markdown files (no custom syntax persisted), metadata in YAML front matter, attached files.

- Editor-only sugar such as `/:command;` from @S-UX-NE2 is **never written to disk**; it is interpreted and stripped before save. Stored markdown remains pure markdown.

### S-DM-N3

Note id: URL path notation, titles separated by slashes from root to leaf: `root-note/.../parent-note/this-note`. Allows referencing notes in spaces as URI: `note://subspace.space/note1/subnote2`.

- Note id is derived from the title slug and is **mutable** (changes on rename/move).
- For stable cross-rename identity use `uuid` (see @S-DM-N5).

### S-DM-N4

Note description: first line under the title in markdown content.

### S-DM-N5

Note metadata (YAML front matter):

- `uuid`: (required) UUID. Autogenerated, immutable. Stable internal key surviving renames/moves, in opposition to `id` which is derived from title and mutable.
- `title`: (required) slug form `^[a-z0-9-]+$`. Synced from the first markdown heading (`# ...`) with normalization (spaces and special characters replaced with hyphens, lowercased). The original heading remains the human-readable display title in content.
- `space`: (required, root note only) synced from placement in storage.
- `labels`: (required) space-separated string; each token matches `^[a-z0-9-]+$`. Represents a set of labels.
- `references`: array of URI references (`note://`, `space://`, `view://`, `file://`). Synced from content.
- `created_at`, `updated_at`: (required) timestamps. Set automatically.
- `draft`: bool. Indicates that a separate draft file exists for this note (see @S-DM-N7). The published file's frontmatter reflects its last published state; the `draft` flag in `notes.json` and the ViewModel is computed from draft-file presence, not from the published file's frontmatter.

### S-DM-N6

Frontmatter format:

- YAML, UTF-8.
- Required fields MUST be present; optional fields MAY be omitted.
- Field order is not significant. `TBD post-POC: escaping rules for strings containing YAML control characters.`

### S-DM-N7

Drafts:

- A draft is a **separate file** alongside the note (see @S-ST-DM4), not inline content.
- At most one draft file per note.
- Frontmatter `draft: true` is written to the draft companion file only; the published file's `draft: false` reflects its last published state and is **not** rewritten when a new draft is created. The `draft` flag in indexes and the ViewModel is computed from draft-file presence.

### Note References

#### S-DM-NR1

Note reference: other note, space, view, attached file, or external resource.

#### S-DM-NR2

Note references in content use standard markdown referencing syntax.

#### S-DM-NR3

Internal references (single URI scheme family):

- `space://<subspace>.<space>[?<query>]`
- `note://<subspace>.<space>/<note>/<subnote>[#<block-id>][?<query>]`
- `view://<view-name>[?<query>]`
- `file://<relative.file.path>` for attached files.
- `[?<query>]` parametrizes the target view (Notes view, Space view) and/or in-note navigation. `TBD post-POC: query grammar.`

#### S-DM-NR4

Note-to-note references are bi-directional and support block-level granularity:

- Forward link: `[text](note://<subspace>.<space>/<note>/<subnote>[#<block-id>][?<query>])` — links to a specific block in the target note.
- Backlink: block-id where the reference is made is stored in the references index.
- Indexed. Synced from content.

#### S-DM-NR5

`TBD post-POC` Block-id production: how `#block-id` is generated and stabilized (manual anchors vs. heading slugs vs. auto-generated stable ids in frontmatter). Required for stable backlinks.

#### S-DM-NR6

`TBD post-POC` Reference composer: interactive helper in the editor allowing the user to compose note references by searching notes and in-note blocks.

### Note Definitions

Provisional implementation currently covers a narrow candidate syntax and index shape; broader syntax options and richer metadata remain deferred.

#### S-DM-ND1

Note definition (provisional candidate syntax): a markdown line matching `**Term** Definition text`, where both the extracted term and definition text are non-empty. `TBD post-POC: alternative syntaxes such as definition lists and configurable patterns via settings.`

#### S-DM-ND2

Note definitions (provisional): indexed and synced from note content on create/update; entries belonging to a deleted note or replaced during re-sync are removed; index keys are normalized to lowercase.

#### S-DM-ND3

Note definition content (provisional): definition entries are keyed by term and retain the extracted definition text plus the source note reference; `block_id` remains unset until @S-DM-NR5 is specified. `TBD post-POC` Statistics model.
